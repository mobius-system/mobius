# 首页个人 Skill / Memory 面板改版规划

## 1. 设计结论

将首页右侧常驻的 Skill / Memory 第三列，改为由页面标题栏入口唤起的「个人上下文」右侧抽屉。首页默认只保留项目列表；抽屉内以 Skill / Memory 两个标签页承载现有管理能力，一次只展示一种内容。

这不是单纯把现有面板拉高或缩窄，而是重新校正它的信息级别：项目是首页的主任务，个人上下文是低频但重要的全局资产，应该随时可达，但不应持续挤压项目浏览空间。

## 2. 页面任务与设计原则

- 使用对象：需要频繁浏览、筛选、进入和创建项目的 Mobius 管理员与开发者。
- 首页唯一主任务：快速找到项目并进入工作。
- 次级任务：维护所有新会话默认可用的个人 Skill 和 Memory。
- 信息层级：项目浏览始终占满主工作区；个人上下文仅在用户主动管理时占用视口。
- 改造边界：不改后端接口、不改 Skill / Memory 数据语义、不影响项目级管理器和会话快照。

## 3. 当前问题

1. 右栏默认宽 340px，位于 `max-w-6xl` 容器内部，与 24px 间距一起持续压缩项目卡片区域；高分辨率下页面外侧仍有空白，主区却只能维持两张偏窄卡片。
2. Skill 和 Memory 是低频管理能力，却与项目列表拥有同等常驻权重，违背首页主任务。
3. 外层已有「个人 Skill / 个人 Memory」标题，内部管理器又显示「用户级 Skill / 用户级 Memory」，形成重复层级。
4. 两个空管理器纵向堆叠，内容结束后留下大块无归属空白；将容器强行拉满只会放大这一问题。
5. 当前眼睛图标表达的是“显示/隐藏”，不能准确表达“管理个人上下文”，首次使用不易理解。
6. 入口使用 `hidden xl:inline-flex`，右栏也使用 `hidden xl:block`；小于 XL 的视口完全失去首页管理入口，不是完整的响应式方案。

## 4. 方案比较

| 方案 | 项目浏览空间 | 空状态观感 | Skill / Memory 操作效率 | 响应式 | 结论 |
| --- | --- | --- | --- | --- | --- |
| A. 现有右栏拉满高度 | 持续被压缩 | 空白被包进更大的面板 | 两类同时可见 | 一般 | 不采用 |
| B. 页面底部横向管理区 | 不压缩首屏 | 需要长距离滚动 | 入口不稳定 | 尚可 | 不采用 |
| C. 独立设置页面 | 最宽 | 干净 | 离开首页、路径变长 | 好 | 作为未来扩展，不作为本次首选 |
| D. 右侧抽屉 + 双标签 | 默认最宽 | 空态集中且有明确操作 | 一次聚焦一类，随开随关 | 好 | 推荐 |

## 5. 推荐布局

### 5.1 首页默认态

```text
┌──────────────┬─────────────────────────────────────────────────────────────┐
│ 项目导航     │ 全部项目                         [个人上下文] [＋ 新项目] │
│ 搜索/筛选    │ 1–16 / 260                                             │
│              │                                                           │
│ 项目列表     │ ┌──────────────────┐  ┌──────────────────┐                  │
│              │ │ 项目卡片         │  │ 项目卡片         │                  │
│              │ └──────────────────┘  └──────────────────┘                  │
│              │ ┌──────────────────┐  ┌──────────────────┐                  │
│              │ │ 项目卡片         │  │ 项目卡片         │                  │
│              │ └──────────────────┘  └──────────────────┘                  │
└──────────────┴─────────────────────────────────────────────────────────────┘
```

- 删除首页内容区中的常驻第三列和对应拖拽宽度。
- 内容容器可继续保持合理最大宽度，但项目网格获得原右栏空间；本次不同时改变项目卡片密度和分页策略。
- 标题栏新增 `个人上下文` 次级按钮，使用 `Library` 或 `BrainCircuit` 图标；不再使用 Eye / EyeOff。
- 按钮可显示轻量计数 `Skill n · Memory n`。计数不是前置条件：若复用管理器数据需要过多改造，首版只显示文字入口，抽屉打开后加载数据。

### 5.2 抽屉打开态

```text
┌────────────────────────── 页面（背景保持可辨，轻遮罩） ─────────────────────┬──────────────┐
│                                                                           │ 个人上下文 × │
│                                                                           │ [Skill n][Memory n]
│                                                                           ├──────────────┤
│                                                                           │ 当前标签页   │
│                                                                           │ 工具栏       │
│                                                                           │              │
│                                                                           │ 列表/空状态  │
│                                                                           │ 独立滚动     │
└───────────────────────────────────────────────────────────────────────────┴──────────────┘
```

- 抽屉从右侧覆盖进入，不重排项目卡片，桌面宽度 `clamp(400px, 34vw, 560px)`。
- 顶部固定：标题、关闭按钮、Skill / Memory 分段标签；正文独立滚动并填满余下高度。
- 标签页记忆用户最后选择，但抽屉每次进入首页默认关闭，确保项目优先。
- 点击遮罩、关闭按钮或按 Esc 关闭；打开时将焦点移至抽屉标题或首个标签，关闭后将焦点还给入口。
- 使用 `role="dialog"`、`aria-modal="true"`、可读的标签名和焦点约束，避免键盘焦点进入背景。
- 正在填写或上传时不因误点遮罩丢失内容：编辑器弹窗沿用现有保护；若管理器存在内联未提交表单，遮罩关闭需要确认或临时禁用。

### 5.3 Skill / Memory 标签

- 一次仅挂载当前标签对应的管理器，避免两个管理器同时请求与占用 DOM。
- 去掉抽屉内部重复的“个人 Skill / 用户级 Skill”两层标题，只保留抽屉标题、标签和管理器操作栏。
- 管理器支持展示模式参数，例如 `variant="panel"`：保留现有卡片模式给项目页，面板模式去掉最外层卡片边框与背景，让内容直接成为抽屉的一部分。
- 操作栏固定在内容顶部，统一为图标加短文字的明确命令：上传、复制、添加/写入。继续使用现有 Lucide 图标和 Tooltip。
- 内容较多时只滚动列表和表单区域，顶部标签与主要操作始终可见。

### 5.4 空状态

- Skill：显示简短状态“尚无个人 Skill”，主操作“添加 Skill”，次操作“上传文件”。
- Memory：显示简短状态“尚无个人 Memory”，主操作“写入 Memory”，次操作“上传文件”。
- 不再重复解释产品概念，不使用大插画或大卡片；空状态高度约 160–200px，在抽屉上部形成明确的行动区，剩余空间保持为抽屉工作区背景。
- “复制已有内容”保留在操作菜单或次级入口，不让空状态同时出现三个同权按钮。

## 6. 响应式行为

| 视口 | 行为 |
| --- | --- |
| `>= 1280px` | 右侧抽屉宽 `clamp(400px, 34vw, 560px)`；项目区不位移 |
| `768–1279px` | 抽屉宽 `min(480px, 72vw)`；入口仍在页面标题栏，不再隐藏 |
| `< 768px` | 抽屉成为全宽工作面板；顶部保留返回/关闭，标签可触控，正文独立滚动 |

- 桌面、Electron 和 Web 使用同一 React 交互，不使用 `-webkit-app-region: drag`。
- 窄屏标题栏优先保留“新项目”和个人上下文两个图标按钮，通过 Tooltip / `aria-label` 表意；有足够宽度时再显示文字。
- 尊重 `prefers-reduced-motion`；常规进入/退出仅使用 160–200ms 位移与遮罩透明度过渡。

## 7. 视觉系统

整体延续 Mobius 的安静、工作台式视觉，不另造一套主题。下面颜色作为亮色主题的设计校准值，代码优先映射现有 CSS 变量；暗色与自定义主题沿用变量体系。

| 角色 | 校准色 | 用法 |
| --- | --- | --- |
| Canvas | `#F6F8FB` | 页面与遮罩下背景 |
| Surface | `#FFFFFF` | 抽屉主体 |
| Ink | `#1E293B` | 主标题与内容名 |
| Muted | `#64748B` | 辅助信息、计数 |
| Line | `#DCE3EC` | 分隔线与输入边界 |
| Action | `#3B82F6` | 当前标签和主操作；Memory 可用 `#7C5CE7` 作轻量识别，但不铺大面积色块 |

- 中文正文与标题继续使用 `Noto Sans SC`；英文和数字使用现有 `Inter`；路径、文件名和技术标识继续使用 `JetBrains Mono`。
- 抽屉标题 16px / 600，标签和操作 12–13px，列表标题 13px / 600，辅助信息 11px。
- 圆角不超过 8px；抽屉本体不做浮动卡片圆角，列表项只在 hover/选中时显示轻背景。
- 不使用渐变、装饰光斑或额外阴影堆叠。唯一的视觉特征是“上下文书脊”：抽屉最左侧 2px 细线随当前标签在蓝色 Skill 与紫色 Memory 间切换，用最小面积提示当前资产类型。

## 8. 实现范围

### 8.1 主要文件

- `mobius/frontend/src/pages/UserPage.tsx`
  - 用 `contextPanelOpen` / `contextPanelTab` 替代 `skillMemoryCollapsed`。
  - 移除右侧 `ResizablePanel` 常驻渲染。
  - 标题栏增加个人上下文入口，并在所有视口可达。
  - 挂载新的右侧面板组件。
- 建议新增 `mobius/frontend/src/components/user-context-drawer.tsx`
  - 负责 Portal、遮罩、Esc、焦点恢复、标签切换、响应式结构。
  - 不负责 Skill / Memory 业务请求与 CRUD。
- `mobius/frontend/src/components/skills.tsx`
- `mobius/frontend/src/components/memories.tsx`
  - 增加最小展示参数 `variant?: 'card' | 'panel'`。
  - 面板模式去除外层卡片皮肤、压缩重复标题、提供可复用的数量回调仅在确有必要时加入。
- `mobius/frontend/src/index.css`
  - 增加上下文抽屉、遮罩、响应式宽度和 reduced-motion 样式；优先复用现有 `.mobius-drawer` 视觉语言。

### 8.2 不改范围

- Skill / Memory 后端 API、文件格式、可见性、复制与移动规则。
- 项目级 Skill / Memory 页面。
- 新建会话时的 Skill / Memory 选择和快照注入逻辑。
- 项目卡片内容、排序、分页与搜索接口。

### 8.3 兼容处理

- 旧键 `mobius:ui:sidebar:user-skills:hidden` 不再参与打开状态；可保留不清理，避免无意义迁移写入。
- 旧宽度键 `mobius:ui:sidebar:user-skills` 不再读取；同样无需主动删除。
- 新增标签记忆键建议为 `mobius:ui:user-context:last-tab`，仅接受 `skill` / `memory`。
- 保留现有 `data-tour="user-skill-manager"`、`user-memory-manager` 及子操作选择器；入口新增稳定选择器 `data-tour="user-context-open"`。

## 9. 分阶段实施

1. 布局骨架：抽出 `UserContextDrawer`，替换眼睛按钮和常驻右栏，完成全视口开关、Esc、遮罩、滚动锁定与焦点恢复。
2. 管理器适配：为两个管理器增加 panel 变体，去除重复卡片层级，整理空状态与操作栏；确保项目级 card 变体无回归。
3. 响应式与可访问性：覆盖桌面、平板、手机，验证键盘、焦点、滚动与 reduced-motion。
4. 视觉回归：在亮色、暗色、自定义主题下截图，确认项目卡片宽度恢复、抽屉层级清晰、文字无溢出。
5. 引导与验证：检查 Driver.js 选择器，构建前端，使用真实登录态验证 CRUD 与窄屏入口。

## 10. 验收标准

- 首页首次进入时不显示常驻 Skill / Memory 第三列，项目列表使用完整主区宽度。
- 自己的首页在桌面、平板、手机均能找到个人上下文入口；查看他人首页不显示入口。
- 抽屉打开不改变项目卡片列宽和滚动位置；关闭后焦点回到触发按钮。
- Skill / Memory 标签切换后仅显示当前管理器，最后使用的标签可恢复。
- 上传、复制、添加/写入、编辑、删除、移动和访问控制行为与改版前一致。
- 空列表只出现一个紧凑空状态，不再出现标题重复和两张空卡片堆叠。
- 项目级 SkillsManager / MemoriesManager 的视觉和行为不发生回归。
- `Esc`、遮罩、关闭按钮均可关闭；内联未提交内容不会被无提示丢弃。
- 360px、768px、1280px、1920px 视口无横向滚动、遮挡或文字溢出。
- 亮色、暗色、自定义主题下对比度与边界清晰；减少动态效果偏好生效。
- `cd mobius/frontend && npm run build` 通过。

## 11. 设计自检

最初可选方向是“让右栏填满剩余高度并加入更多摘要”，但这仍把低频资产管理当成首页第三主栏，无法解决项目卡片被长期压缩的问题，因此舍弃。

最终方案的特定性来自 Mobius 的上下文模型：Skill 与 Memory 都是“影响后续新会话的个人资产”，它们天然属于一个上下文中心，而不是两个并列的首页内容栏目。抽屉左侧随标签切换的细书脊线只强化这一语义，其余视觉保持克制，避免把运营工作台做成通用仪表盘模板。
