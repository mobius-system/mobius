# Mobius 3～5 分钟宣传视频文案与分镜设计

日期：2026-07-25

版本：V3 审核稿

依据：Mobius `README.zh.md`、用户提供的功能大纲与本轮确认的产品定位

## 1. 成片目标

制作一条约 4 分 20 秒的 Mobius 产品宣传视频，面向广泛的 AI 工具用户，用真实项目工作流解释 Mobius 与现有执行型 Agent、个人智能体产品的层级和设计目标差异。

视频首先承认现有 AI Agent 已经能够执行复杂任务，再提出“多数系统的形态仍由开发者预先定义”这一矛盾，以“如果系统可以由用户持续塑造”抓住注意力。随后通过一个项目从接入、拆解、执行、验证到跨设备协作的完整过程，呈现 Mobius 的核心价值。

最终希望观众形成三个明确认知：

1. Mobius 可以由用户持续塑造，按照用户的想法改变功能、界面、流程与拓展，并随需求不断进化。
2. Mobius 不是又一个单独工作的 AI Agent，而是承载和组织不同智能体能力的操作系统。
3. Mobius 打通 Web、PC 与移动端，既可以成为个人生产力系统，也可以承载长期项目和团队协作。

## 2. 已确认的核心定位

主定位：

> Mobius，一个由用户持续塑造、随需求不断进化的智能体操作系统。

品牌主张：

> Mobius，塑造属于你的 Agent OS。

价值解释：

> 它打通 Web、PC 与移动端，既可以服务个人，也可以把团队成员、AI 智能体、项目、模型、设备与算力连接在同一个持续工作的空间里。

开场主张：

> AI Agent 已经会工作。下一步，让 AI 系统学会改变自己。

辅助记忆点：

> 不是让你适应一套固定的 AI 系统，而是让 AI 系统持续适应你。

## 3. 受众与表达原则

- 核心受众：广泛的 AI 工具用户、潜在产品用户、创业团队及对智能体协作感兴趣的人。
- 主要场景：官网、产品发布、项目路演、长视频平台和线下展示。
- 主成片比例：16:9，建议 1920×1080 或 3840×2160。
- 语言：中文普通话旁白，屏幕标题使用简体中文；产品原生界面可保留中英混合内容。
- 表达方式：先讲用户价值，再展示功能；技术概念通过实际结果解释，不做教程式逐按钮讲解。
- 竞品表达：不直接贬低 Claude Code、Codex 等工具。将它们描述为可被 Mobius 接入的优秀模型或执行智能体，突出产品层级和设计目标不同。

## 4. 贯穿全片的演示项目

主案例设定为：

> 一位用户把一个已有的 AI 产品项目接入 Mobius，要求团队和智能体共同优化产品介绍网站，并完成检查、修改和发布前验证。

采用这个案例的原因：

- 前后视觉变化明显，适合宣传视频。
- 可以自然展示本地文件、工作区、Git、任务拆解、前端预览、截图反馈和 Playwright 验证。
- 可以进一步连接远程服务器与科研系统，而不需要切换到毫不相关的案例。
- “让系统参与改进系统”可以呼应 Mobius 的自进化定位。

项目创建的两种方式采用分屏快速展示：左侧拖入本地文件，右侧由桌面端设置本地工作区。主线后续使用“设置本地工作区”的项目继续演示。

### 4.1 自进化证明案例

采用已经真实完成、可复现的 Mobius 自身界面修改作为开场后的第一项能力证明：

> 用户截取会话页面右侧操作区，标注“四个操作入口太占空间，希望改成紧凑的 2×2 布局”，随后把截图和要求发送给小莫。Mobius 修改自身前端，页面刷新后四个入口变成 2×2 布局。用户继续反馈“按钮文案长度更均衡”，系统再次调整并保留最终结果。

选择该案例的原因：

- 修改对象是 Mobius 自身界面，而不是普通业务项目，能够直接证明“系统由用户塑造”。
- 已存在修改前、提出需求、修改后和二次反馈素材，录制风险低。
- 两轮连续反馈可以证明这不是一次性生成，而是系统能够按照用户意见继续迭代。
- 原始变化集中在右侧操作区，正式成片必须使用局部放大、截图标注和修改前后分屏，避免全屏录制导致变化不明显。

镜头中使用的用户要求：

> 右侧这四个操作入口太占空间了，请改成紧凑的 2×2 布局，让按钮文案长度也尽量均衡。

## 5. 视觉与声音方向

### 5.1 画面结构

- 约 75% 使用真实 Mobius UI 录屏，建立可信度。
- 约 25% 使用标题动画、设备合成、关系线和局部放大，帮助大众理解抽象能力。
- 开头 30 秒采用 1～2.5 秒的快速切镜；进入产品演示后，单镜头保持 3～6 秒，保证观众看清变化。
- 重要操作不展示冗长等待过程，使用速度渐变、时间压缩和任务状态跳切。
- 鼠标移动必须有目的；关键点击增加轻微光圈，不使用连续夸张点击特效。

### 5.2 视觉气质

- 基调：深色、克制、现代、具有系统感。
- 动效语言：节点连接、卡片展开、任务流转、设备之间的光线迁移。
- 关键色沿用 Mobius 品牌和产品界面，不额外引入过多霓虹色。
- 屏幕文字每次只表达一个观点，尽量控制在 6～14 个汉字。

### 5.3 声音

- 音乐：从低频电子脉冲开始，产品出现后加入稳定节拍，任务并行时提升层次，结尾回到开阔、坚定的和弦。
- 音效：轻量键盘声、点击声、任务创建提示、连接成功提示和转场呼吸声。
- 旁白：自然、坚定、有思考感；避免过度热血或传统广告腔。
- 关键句前后保留 0.3～0.6 秒空间，让观众有时间理解。

## 6. 详细时间轴、旁白与镜头

### 镜头 01：AI Agent 已经会工作

- 时间：00:00～00:12
- 目的：先承认现有 Agent 的真实能力，建立可信度并抓住大众用户。
- 旁白：

  > 今天的 AI Agent，已经能够写代码、调用工具，甚至独立完成复杂任务。

- 画面：
  1. 黑场中出现一句自然语言任务。
  2. 快速闪过 Agent 读取文件、修改代码、执行终端命令和操作浏览器的画面。
  3. 使用真实或通用化的 Agent 工作界面，不把现有产品表现成只能聊天。
  4. 最后定格在一个已经完成的任务结果上。
- 屏幕文字：`AI Agent，已经开始工作`
- 声音：单个低频脉冲；文件、终端和浏览器画面依次加入轻量操作音效。

### 镜头 02：系统仍由别人定义

- 时间：00:12～00:25
- 目的：指出 Mobius 真正要解决的问题不是 Agent 不会执行，而是系统难以由用户持续塑造。
- 旁白：

  > 但多数系统的界面、流程和能力边界，仍由别人预先定义。如果不再是你适应 AI，而是 AI 系统按照你的想法持续改变呢？

- 画面：
  1. 多种 AI 工具以固定窗口或固定工作流的形式快速切换。
  2. 用户尝试在工具、终端、项目管理和聊天窗口之间拼接自己的工作方式。
  3. “按照你的想法”处出现需求文字、标注截图和参考链接。
  4. 固定框架开始松动和重新组合，为 Mobius 揭示蓄势。
- 屏幕文字：`如果，系统可以由你塑造？`

### 镜头 03：Mobius 产品揭示

- 时间：00:25～00:43
- 目的：明确产品是什么。
- 旁白：

  > 这是 Mobius。一个由用户持续塑造、随需求不断进化的智能体操作系统。它打通 Web、PC 与移动端，既服务个人，也支持项目和团队协作。

- 画面：
  1. Mobius Logo 与主界面干净出现。
  2. 主界面缩入笔记本电脑画框。
  3. 两侧依次出现浏览器页面和手机界面，三个设备保持同一个项目状态。
  4. 轻推镜头进入桌面端项目页面。
- 屏幕文字依次出现：
  - `由用户持续塑造`
  - `随需求不断进化`
  - `Web · PC · 移动端`
  - `个人 · 项目 · 团队`

### 镜头 04：系统适应用户，而不是用户适应系统

- 时间：00:43～01:02
- 目的：尽早呈现最独特的“自进化”能力。
- 旁白：

  > 给它一个需求、一张截图或一个参考链接。Mobius 不只完成这次任务，还能把你的想法变成新的代码、界面、拓展和工作流程，逐渐长成你需要的样子。

- 画面：
  1. 全屏展示修改前的 Mobius 会话页，随后平滑放大右侧纵向排列的四个操作入口。
  2. 截取该区域，在截图上标注“太占空间，改成 2×2”。
  3. 打开小莫，把截图与要求一起发送；输入过程只保留最有辨识度的 2～3 秒。
  4. 使用时间压缩快速闪过 Mobius 修改自身代码、构建和验证的过程。
  5. 页面刷新，镜头再次放大同一区域，四个入口已经变成紧凑的 2×2 布局。
  6. 使用垂直分屏展示修改前与修改后，中央短暂出现“系统界面已更新”。
  7. 快速带过第二轮反馈“按钮文案长度更均衡”和最终结果，证明系统可以继续迭代。
- 屏幕文字：`由用户持续塑造`
- 制作提醒：使用真实可复现的自进化素材；修改前、标注截图、发送需求、修改后必须来自同一页面和同一区域。全屏画面之后必须局部放大，避免 2×2 布局变化在手机或投影观看时不明显。

### 镜头 05：桌面端接入项目，两种创建方式

- 时间：01:02～01:24
- 目的：介绍桌面端以及创建项目的两种方式。
- 旁白：

  > 一个项目，可以从上传本地文件开始，也可以通过桌面端直接设置工作区。Mobius 读取真实的项目文件，让你的电脑成为智能体可以协作的工作节点。

- 画面：
  1. 分屏：左侧把项目文件拖入上传区；右侧在桌面端选择本地工作区。
  2. 两侧都出现项目创建成功状态。
  3. 左侧淡出，右侧桌面端展开为全屏，进入后续主线。
  4. 快速带过 Windows、macOS、Linux 的系统标识或安装包界面。
- 屏幕文字：
  - `上传本地文件`
  - `设置本地工作区`
  - `让 PC 成为工作节点`

### 镜头 06：创建第一个任务并初始化项目

- 时间：01:24～01:44
- 目的：展示自然语言目标如何变成正式任务。
- 旁白：

  > 不需要先整理复杂配置。告诉小莫你的目标，Mobius 就能创建第一个任务，初始化项目和 Git，并把工作放进一个可追溯的执行过程。

- 画面：
  1. 用户输入：“分析这个项目，并为产品介绍页制定优化方案。”
  2. 点击创建任务。
  3. 项目初始化、Git 初始化和任务启动状态依次完成。
  4. Agent 状态从等待变为运行。
- 屏幕文字：`一句目标，启动一个项目`
- 音效：任务创建和 Agent 启动分别使用轻提示音。

### 镜头 07：浏览文件与查看 Git

- 时间：01:44～02:03
- 目的：证明工作建立在真实项目上，并且过程可追溯。
- 旁白：

  > 智能体可以理解并修改真实文件。你也能随时浏览目录、查看内容和检查 Git 变化。每一次修改来自哪里、改变了什么，都清晰可见。

- 画面：
  1. 三栏工作区出现：文件浏览器、代码或文档编辑器、对话区域。
  2. 打开产品文案文件和前端组件。
  3. 切换到 Git 视图，展示新增、修改和差异对比。
  4. 局部放大一处从旧文案到新文案的变化。
- 屏幕文字：`真实文件 · 清晰记录 · 随时追溯`

### 镜头 08：快速创建大量任务

- 时间：02:03～02:23
- 目的：从单一 Agent 升级到项目和团队协作。
- 旁白：

  > 当目标变得复杂，Mobius 可以快速拆分出大量任务，让不同成员和智能体分别研究、设计、开发和检查。负责人只需要把握方向，而不必追逐每一条零散消息。

- 画面：
  1. 用户输入：“把产品介绍页优化拆成研究、文案、设计、开发和验证任务。”
  2. 多张任务卡片快速生成，但动画需分批出现，避免视觉噪声。
  3. 任务分配到不同成员或 Agent。
  4. 团队视图展示运行中、待确认和已完成状态。
- 屏幕文字：`一个目标，展开一张任务网络`

### 镜头 09：打开前端并实时调试

- 时间：02:23～02:44
- 目的：呈现最直观的“工作结果”。
- 旁白：

  > 修改不再只存在于代码里。直接打开前端，边讨论、边修改、边查看结果。想法与实际页面之间，只隔着一次自然语言反馈。

- 画面：
  1. 从代码或任务区域打开前端预览。
  2. 展示修改前的产品页面。
  3. 用户提出：“首屏信息太散，突出团队与智能体协作。”
  4. 代码发生变化，页面热更新为新版布局。
  5. 镜头在最终首屏停留 2 秒。
- 屏幕文字：`边沟通 · 边修改 · 边验证`

### 镜头 10：截图与 Playwright 闭环反馈

- 时间：02:44～03:07
- 目的：强调 AI 不只修改，还会观察结果并继续修正。
- 旁白：

  > 你可以直接截下不满意的地方。Mobius 读取反馈，再通过浏览器和 Playwright 打开页面、检查状态、保存截图，并把结果带回项目上下文，继续完成下一轮修正。

- 画面：
  1. 在预览页框选一个按钮或版式问题并截图。
  2. 截图作为反馈发送给 Agent。
  3. Playwright 自动打开页面、滚动、点击和检查响应式布局。
  4. 依次出现“修改前截图”“验证中”“修改后截图”。
  5. 最终任务状态变为验证完成。
- 屏幕文字：`看见问题 → 修改 → 验证 → 继续迭代`
- 制作提醒：保留一次真实失败或发现问题的瞬间，再展示修正，更能体现闭环价值。

### 镜头 11：与外部服务器和算力协作

- 时间：03:07～03:27
- 目的：把项目从单台电脑扩展到设备与算力网络。
- 旁白：

  > 当任务需要更多资源，Mobius 可以连接工作站、云服务器和 GPU 算力。通过 SSH、AIMUX 与可控代理，让本地项目与远程设备在同一个任务网络里协作。

- 画面：
  1. 从当前项目打开设备或远程资源界面。
  2. 本地 PC、云服务器和 GPU 节点依次连接成功。
  3. 一个计算或构建任务从本地流转到远程服务器。
  4. 结果返回项目，任务卡片更新。
- 屏幕文字：`连接设备，也连接算力`

### 镜头 12：自动科研系统

- 时间：03:27～03:47
- 目的：展示 Mobius 不局限于软件开发。
- 旁白：

  > 它也可以把一个科研目标，组织成多智能体协作的研究系统。阅读资料、提取方法、分析数据、运行实验，再把结果汇总为可以继续推进的结论。

- 画面：
  1. 输入一个与 AI 产品交互或智能体协作相关的研究目标。
  2. 多个研究 Agent 节点展开。
  3. 快速展示论文、方法卡片、研究关系图和汇总结论。
  4. 研究结果被关联回主项目任务。
- 屏幕文字：`从一次检索，到一条自主科研流水线`

### 镜头 13：小莫、团队与移动端

- 时间：03:47～04:07
- 目的：完成跨端协作闭环，并赋予产品人格入口。
- 旁白：

  > 小莫是整个系统的自然语言入口。创建项目、拆分任务、启动智能体、追踪进度，都可以直接交给它。离开电脑以后，你仍然可以在手机上查看进展、补充要求和确认决策。

- 画面：
  1. 桌面端小莫面板中询问：“目前还有哪些任务需要确认？”
  2. 切到网页端团队状态总览。
  3. 转场至手机，显示同一个项目的进度和待确认事项。
  4. 用户在手机上批准一个决定，桌面端任务继续运行。
- 屏幕文字：
  - `能点的，小莫都能做`
  - `Web · PC · 移动端，项目持续在线`

### 镜头 14：品牌收束与行动引导

- 时间：04:07～04:20
- 目的：留下清晰的产品定位和品牌记忆。
- 旁白：

  > 不是让你适应一套固定的 AI 系统，而是让系统按照你的想法持续成长。无论是个人任务、长期项目，还是团队协作，Mobius 都可以被塑造成你需要的样子。

- 画面：
  1. 前面出现过的团队、Agent、电脑、手机和服务器节点汇入 Mobius 环形轨迹。
  2. Mobius Logo 居中出现。
  3. 最后显示 GitHub、官网和文档入口。
- 主屏文字：`Mobius，塑造属于你的 Agent OS`
- 副屏文字：`一个由用户持续塑造、随需求不断进化的智能体操作系统`
- 行动引导：`访问官网 · 查看 GitHub · 开始创建你的项目`

今天的 AI Agent，已经能够写代码、调用工具，甚至独立完成复杂任务。

但多数系统的界面、流程和能力边界，仍由别人预先定义。如果不再是你适应 AI，而是 AI 系统按照你的想法持续改变呢？

这是 Mobius。一个由用户持续塑造、随需求不断进化的智能体操作系统。它打通 Web、PC 与移动端，既服务个人，也支持项目和团队协作。

给它一个需求、一张截图或一个参考链接。Mobius 不只完成这次任务，还能把你的想法变成新的代码、界面、拓展和工作流程，逐渐长成你需要的样子。

一个项目，可以从上传本地文件开始，也可以通过桌面端直接设置工作区。Mobius 读取真实的项目文件，让你的电脑成为智能体可以协作的工作节点。

不需要先整理复杂配置。告诉小莫你的目标，Mobius 就能创建第一个任务，初始化项目和 Git，并把工作放进一个可追溯的执行过程。

智能体可以理解并修改真实文件。你也能随时浏览目录、查看内容和检查 Git 变化。每一次修改来自哪里、改变了什么，都清晰可见。

当目标变得复杂，Mobius 可以快速拆分出大量任务，让不同成员和智能体分别研究、设计、开发和检查。负责人只需要把握方向，而不必追逐每一条零散消息。

修改不再只存在于代码里。直接打开前端，边讨论、边修改、边查看结果。想法与实际页面之间，只隔着一次自然语言反馈。

你可以直接截下不满意的地方。Mobius 读取反馈，再通过浏览器和 Playwright 打开页面、检查状态、保存截图，并把结果带回项目上下文，继续完成下一轮修正。

当任务需要更多资源，Mobius 可以连接工作站、云服务器和 GPU 算力。通过 SSH、AIMUX 与可控代理，让本地项目与远程设备在同一个任务网络里协作。

它也可以把一个科研目标，组织成多智能体协作的研究系统。阅读资料、提取方法、分析数据、运行实验，再把结果汇总为可以继续推进的结论。

小莫是整个系统的自然语言入口。创建项目、拆分任务、启动智能体、追踪进度，都可以直接交给它。离开电脑以后，你仍然可以在手机上查看进展、补充要求和确认决策。

不是让你适应一套固定的 AI 系统，而是让系统按照你的想法持续成长。无论是个人任务、长期项目，还是团队协作，Mobius 都可以被塑造成你需要的样子。

## 8. 录制素材清单

必须录制：

1. Mobius Web 主界面与项目页。
2. Windows、macOS 或 Linux 桌面端至少一种完整操作，其他系统可用安装包或设备合成画面补充。
3. 上传本地文件创建项目。
4. 设置本地工作区创建项目。
5. 创建首个任务、初始化项目与 Git。
6. 文件浏览器、内置编辑器和对话三栏工作区。
7. Git 状态与 diff 对比。
8. 一次批量拆分任务及多个 Agent 运行状态。
9. 前端页面修改前、修改中和修改后。
10. 截图反馈与一次完整 Playwright 验证闭环。
11. 外部服务器或工作站连接成功及任务执行结果。
12. 科研系统中的多 Agent、研究图谱或汇总结果。
13. 小莫桌面或网页交互。
14. 手机端查看任务、补充要求或确认决策。
15. 自进化前后对比：右侧四个操作入口由纵向排列改为紧凑 2×2 布局，并展示第二轮文案均衡反馈。

辅助素材：

- Mobius Logo 的透明背景高分辨率版本。
- Web、PC、手机设备外框。
- 项目成员头像与 Agent 头像。
- GitHub、官网和文档地址。
- 无敏感数据的演示项目、服务器名称、任务内容和日志。

## 9. 制作与安全注意事项

- 所有录屏使用专门的演示账号和演示项目，不出现真实 Token、密码、IP、内网地址、用户名或客户数据。
- 录屏前关闭系统通知、聊天弹窗和无关浏览器标签页。
- 终端命令和日志只保留观众能理解的关键部分，长日志使用快速滚动或局部裁切。
- UI 录制建议使用 60fps；最终成片可以输出 30fps 或 60fps。
- 浏览器缩放和系统字号应保证 1080p 下任务标题、状态和按钮可读。
- 每个重要功能至少留下一个明确的“输入—执行—结果”链路，避免只展示静态页面。
- 自进化案例必须对同一界面区域使用一致的裁切和缩放比例，确保观众能直接比较修改前后。
- 涉及 Claude Code、Codex 等名称时，以“可接入的执行智能体或模型能力”呈现，不制作贬低性对比画面。
- 手机端只展示当前实际可用的能力，不在画面或旁白中暗示尚未发布的原生功能。

## 10. 审核标准

成片脚本进入录制前，应满足：

- 前 15 秒即出现明确冲突或问题。
- 开场承认现有 Agent 已具备执行能力，不把 Claude Code、Codex 或 Claw 类产品描述成只能对话。
- 45 秒内说清 Mobius 是什么。
- 45 秒内明确表达“由用户持续塑造、随需求不断进化”这一核心定位。
- “Web、PC、移动端”“个人、项目、团队”作为产品覆盖范围被清楚表达，但不取代自进化的核心位置。
- 用户原始大纲中的 11 组能力全部有对应镜头。
- 每一个技术能力都对应一个大众用户可以理解的价值。
- 全片不是功能罗列，而是同一个项目持续推进的故事。
- 结尾包含清晰的品牌定位、主张与行动引导。
- 所有演示均可真实复现，不以概念动画代替尚不存在的产品能力。
